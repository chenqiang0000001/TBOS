# 系统之美知识库

这是个人长期知识、判断、决策与成长系统的本地工作库。目录参考桌面“宏远知识库”的分层方式，同时保留原有 `知识库/` 编号体系，避免迁移时改写历史编号和内部链接。

## 从这里开始

1. [项目概览](项目概览.md)：范围、迁移状态和当前边界。
2. [迁移映射](架构与规范/迁移映射.md)：原工作区内容如何进入本库。
3. [系统导航](知识库/00-系统导航.md)：个人知识条目、问题、决策和行动的实际入口。
4. [审核入口](知识库/80-审核与权重/00-审核入口.md)：先处理真实性、标签和待核验项。
5. [迁移清单](证据索引/迁移清单.md)：文件数量、排除项和来源位置。

## 顶层结构

| 目录 | 用途 |
|---|---|
| `架构与规范/` | 系统设计、维护规则、命名和迁移约定 |
| `模板/` | 新建来源、观点、模型、决策、行动和复盘记录时使用的模板 |
| `业务流程与规则/` | 输入、加工、判断、行动和反馈的运行循环说明 |
| `需求与测试/` | 将知识转为可交付行动、实验和可观察结果的验收约定 |
| `问题复核/` | 问题地图、冲突口径、真实性审核和高影响事项 |
| `证据索引/` | 来源、迁移批次、研究证据和可追溯入口 |
| `原始资料/` | 原始材料的归档说明；当前原件仍按来源 ID 保存在 `知识库/10-原始资料/` |
| `知识库/` | 已迁移的个人知识条目主库，保留原编号和链接 |
| `_research/` | 外部研究、网页转写、计算和核验材料；不等同于已采纳结论 |
| `数据库字典/` | 预留的结构化索引位置；当前不虚构个人数据库字典 |

## 使用边界

- 原始材料、AI 建议、本人确认、外部研究和个人结论分开保存。
- “已确认”只表示本人明确提供或明确采纳的范围；未核验的历史细节、外部事实和分析建议仍保留原状态。
- `_research/` 是证据工作区，不代表其中所有内容都已进入个人知识库。
- 跨境电商试验中的代码、访问凭据和运行数据没有迁移；只迁移了两份规划文档。
- 目标库是独立副本，原工作区 `C:\Users\chq18\Desktop\系统之美终身成长` 保持不变。

## 长期维护

先从真实问题出发，回到来源，写出观点，再记录决策、行动和复盘。只有在检索、关系追溯或批量统计出现稳定瓶颈时，才增加脚本或 SQLite；不要为了扩大目录而扩大维护成本。
